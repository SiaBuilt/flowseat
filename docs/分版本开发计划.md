## 当前启动策略

用户现状：只有一个自己的域名；没有小程序账号、云环境和支付账户。首轮采用开发／体验版验证，不先采购独立服务器，不接入现有域名，不立即做收费。云开发只开满足验证所需的环境，实际套餐与费用在创建前检查，不假设永久免费。

第一轮交付缩到 V0.1＋V0.2：上海地点地图／列表、基础条件与来源日期、收藏／分享，以及简单的结构化纠错入口。反馈先进入指定账号的待处理队列，由该账号处理后更新地点；暂不做公开评论动态、用户互相点赞与自动两票闭店。这些机制保留在 V0.3，不取消长期共创方向。反馈能力本身的服务类目与隐私要求仍要核验，不宣称取消公开评论就自动豁免。

首轮体验不收费，不模拟付费或让用户为未交付功能付款；19.99 元买断仍是后续需要验证的商业模式。免费使用只能证明工具价值，不能证明购买意愿。正式公众发布与好友体验版分别推进，不把体验版称为已公开上线。

首轮先邀请约 10—20 位有实际上海外出办公需求的人试用，记录能否找到地点、实际到访、白跑原因、纠错情况及项目方处理工时。人数是试验建议，不是平台配额或统计充分性标准。

账号准备顺序：注册小程序并核验主体／类目 → 安装开发者工具 → 接入一个开发云环境 → 真机体验 → 完成公开发布所需备案与资料。生产隔离、完整共创与收费在进入对应阶段时落实。

首轮净开发工时仍按原估计约 6—9 个工作日，不包含用户注册、平台等待和真实地点内容整理。当前骨架已完成一部分；不据此保证固定上线日期。

## 重点技术风险与验收

登录不等于头像昵称授权。账号资料和发表署名分别保存；客户端传入的 userId、审核角色、购买状态都不能作授权依据。

失效规则不仅做点击计数：用户独立性、来源去重、证据时间、冲突、恢复和审核覆盖都要有数据记录。两份有效记录可隐藏，但不能保证程序自动识别所有转帖；无法判断同源的反馈进入复核。

收费后仅前端隐藏详情不足以保护权益。服务端必须将预览字段与付费字段分开返回，数据库不允许客户端绕开云函数。退款、换手机与再次登录后的权益以同一微信身份恢复。

数据导入只收允许使用的信息，不复制第三方评论正文。初始地点量和近期证据覆盖率分别统计；付款前让用户看见上海实际覆盖范围。
