# Web 首发与跨端技术方案

当前方向：Web 优先验证，随后微信小程序、Android／iOS App。品牌采用「流动工位 · FlowSeat」；Laptop Friendly 保留为产品定位。

## 选型

客户端采用 uni-app（经典版）＋ Vue 3 ＋ TypeScript，基于 DCloud 官方 vite-ts 模板。已安装的编译器系列锁定为 `3.0.0-5020420260813003`，保留 npm 锁文件，不混用不同日期的 DCloud 包。

选经典 uni-app，是为了先交付轻量 Web，并复用页面到小程序与 App；不在首发引入 uni-app x／UTS 的另一套原生开发和组件适配成本。App 页面可使用 uni-app 的 WebView 渲染，地图等平台组件仍需适配；不宣称这是全部纯原生界面。

| 层 | 复用范围 | 平台差异 |
|---|---|---|
| 页面和样式 | 地图列表、详情、筛选、设施、共创、账号内审核 | 响应式布局、原生地图层级、导航与安全区域 |
| 业务领域 | 地点、费用、插座、工作区域、椅子体验、失效证据规则 | 不依赖 DOM／wx／plus |
| 数据服务 | 统一 HTTP API、响应类型、用户与权益模型 | 每个平台的会话传输适配 |
| 设备能力 | 存储、复制、定位、地图、分享、上传 | 通过适配层封装 |
| 账号 | 服务端内部 userId | Web 邮箱身份、微信 OpenID、未来 Apple／其他 App 登录绑定到同一个用户 |
| 支付 | 服务端订单、权益、发货与退款状态 | Web／微信小程序／App 分别使用获准支付通道 |

后端方向为 Node.js＋TypeScript HTTP API，托管数据库候选 PostgreSQL；保持单个服务，不引入微服务。具体服务商按域名备案、部署地区、成本和国内访问选择，本轮没有开通资源。旧微信云函数骨架保留供参考，不是 Web 当前后端，不直接用 OPENID 作为所有平台的用户主键。

## 实际目录

`apps/client`：新的跨端主工程；`src/domain`：平台无关类型；`src/services`：数据入口；`src/adapters`：平台能力；`src/pages`：页面。

根目录 `miniprogram`、`cloudfunctions` 和相关测试是早期原生小程序准备稿，保留但不再作为当前首发入口。后续服务器能复用规则思路，不声称其身份和部署代码可直接服务 Web。

## 开发约束

1. 页面统一采用 uni-app 支持的组件，不在业务逻辑直接调用 document、window、微信 SDK 或 App SDK。
2. 条件编译集中在适配层；网页库只用于相应平台，不将浏览器地图依赖强行带入小程序。
3. 全端统一费用枚举与 GCJ-02 地点坐标；地图引擎、授权、Key 与导航行为分别接入。
4. 在 Web 首发阶段持续构建 mp-weixin，及时暴露模板与依赖问题；编译成功不等于真机或审核通过。
5. 审核角色、公开数据、付费详情、订单与退款均由服务端控制，不能用本地存储授予权益。
6. App 启用前再添加所需原生权限与 SDK，不保留模板中无关的相机、账号、电话等权限。

## 当前产品字段

收录门槛：允许电脑办公，桌面可放电脑与鼠标。未知信息可以作为候选线索，但不能自动宣称已达到门槛。

地图：费用与地点类型两维识别。费用保持免费／需消费／付费工位／未知，不把消费后使用当免费。

详情核心：插座数量与充电可达性；椅子舒适度；工作区域多选（安静工作／多人讨论／独立通话）；Wi-Fi 连接入口。工作区域可以共存，不要求每个地点只有一种区域。

Wi-Fi：Web 只能展示与复制连接资料，不能通用地连接手机网络。小程序／App 后续核对系统支持和用户授权后实现对应连接适配；不宣称三端自动连接。仅提供场地方允许公开的资料，不把用户未经确认上传的密码自动公开。

当前 Wi-Fi 网络名和密码为显式演示，不是真实场地凭证。

## 验证与部署边界

当前 Web 是交互预览：四个虚构地点、本机收藏、筛选、地点详情、Wi-Fi 示例弹层与演示纠错。示意地图不用于导航；没有真实用户、投稿、支付与数据库。

Web 构建产物可静态托管；私有 Sites 预览用于审阅，不代表已用用户域名公开运营。后续真实地图与共创接口接入后，才是可验证线下使用的 MVP。

微信小程序仍需要 AppID、类目与平台配置；App 仍需要包名、签名、权限、商店账户、支付和发布审核。一套源码减少重复开发，不消除这些步骤。

参考：[uni-app 官方 CLI 与多端构建](https://uniapp.dcloud.net.cn/quickstart-cli.html)、[uni-app 官方地图平台差异](https://uniapp.dcloud.io/component/map.html)、[Taro 官方跨端介绍](https://docs.taro.zone/)。本项目选择 uni-app，不同时维护 Taro。
