## 微信登录：需要先明确的条件

电脑浏览器的微信扫码登录对应“微信开放平台 → 网站应用”；微信内直接授权对应公众号网页授权，是不同的能力，不能用一个按钮假装都已接通。先确认可用于申请的主体和平台实际批准的能力，再决定首轮覆盖哪一种入口。

需要申请人完成账号注册、主体认证、应用资料和平台审核。只需提供审核后的公开 AppID；AppSecret 后续通过正式服务的加密环境配置，不放进前端、Git 或聊天记录。网站应用回调域计划使用 `siabuilt.com`，但应在正式部署方案确定、域名和 HTTPS 验证完成后提交最终配置。

### 现有托管的技术边界

当前 Sites 以平台请求身份作为所有写入、收藏和审核的身份依据。其提供的接入文档要求保留平台认证，当前可用的原生能力未提供微信身份提供方配置。没有在这个私有预览里另造微信 session，也没有通过前端传 userId 来绕过认证。

正式微信版需要支持自有认证的部署环境，或托管平台后续明确支持微信身份。迁移时保留 uni-app 客户端和业务规则；替换服务端身份适配层、运行时数据库适配及部署配置，迁移生产数据。平台身份与微信身份必须经本人授权绑定，不能按昵称自动合并；微信 openid 也不直接作为跨端统一用户主键。迁移后的审核员重新通过服务端授权。

实施顺序：确认主体和获批登录渠道 → 确定可用托管 → 域名/HTTPS → OAuth state、回调、服务端换码、HttpOnly 会话和退出 → 身份绑定/审核员授权 → 真实手机与桌面联调 → 公开访问。没有已批准的 AppID/Secret 时不展示可用的微信登录按钮。
