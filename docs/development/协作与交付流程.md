# FlowSeat 协作与交付流程

生效：2026-11-11。用户要求每次交付完整走完 UI / QA 验收并沉淀文档。

## 四个角色，三个执行 agent

| 角色 | 责任 | 必须交回的结果 |
| --- | --- | --- |
| 主 agent / 交付负责人 | 梳理现状和验收标准、划分文件归属、整合修改、管理版本与部署、最终检查 | 版本与环境、各项验收结论、剩余问题、交付文档链接 |
| 全栈 agent | 检查调用方与数据流，做最小完整修复；维护数据来源与构建同步 | 改动与原因、影响范围、自检结果、交给 QA/UI 的复现步骤 |
| QA agent | 独立检查正常、异常、权限和状态变化；执行适当回归 | 用例、期望、实际、环境/版本、通过或失败证据 |
| UI agent | 在实际浏览器操作受影响页面，检查桌面及移动布局、交互和错误状态 | 操作路径、实际结果、截图、浏览器/尺寸；明确是否手机真机 |

共享目录中先约定修改文件，不同时改同一个文件。生产浏览器只由一个 agent 操作。主 agent 负责调用 Sites 发布工具，不由多个 agent 重复发布。完成的 agent 需要新任务时使用 followup_task 唤醒。

## 每轮顺序

1. **核对基线。** 读取 PROJECT_MEMORY、当前分支和未提交修改、最新发布记录；明确本轮目标和完成条件，不覆盖用户改动。
2. **实现与自检。** 复用已有实现，只修必要范围。非平凡逻辑留有效回归；简单文案不增加无意义测试。
3. **独立 QA。** 实现者的自检不代替 QA。涉及投稿/审核需检查匿名、普通用户、审核员、所有权、重复请求及过期状态；必须从服务端验证权限。
4. **真实 UI。** 操作实际页面，覆盖入口、主流程、空态/错误态及桌面和移动宽度。截图前等待页面稳定，检查是否完整、是否动画中或失真。文档/截图任务验收渲染结果、图片与链接，不为无关业务重跑所有流程。
5. **修复回路。** QA/UI 问题带步骤和证据交回全栈，修复后由发现方复验。新改动影响已通过用例时重新检查相关部分。
6. **发布复验。** 确认交付代码版本和发布源一致，完成必要构建/同步；合入约定主分支并部署。检查发布状态、关键接口和实际页面。改变访问范围时验收匿名/普通用户路径，不把本人可访问等同于公众可用。
7. **文档与交付。** 更新本轮报告和 PROJECT_MEMORY，记录完成、失败、阻塞、未验证。交付链接、实际版本和必要限制，不要求用户代替团队做常规验收。

## 本项目的验收底线

- 真账号审核用现有唯一测试记录续做，不重复污染队列。执行投稿/退回/修改重提/通过/隐藏/恢复/再隐藏，最后确认测试稿不在公开列表，审计记录保留。
- 本地模拟身份、接口测试、截图目标数据不能代替生产真实用户验收。不得伪造生产身份头。
- 真实手机、浏览器移动宽度仿真分别记录；没有真机证据就写未验证。
- 地点真实来源、商家自述、用户体验和截图设想分开记录。目标效果数据不得同步到生产。
- 保留实验视觉分支；没有用户方向不能用原型替换功能主线。
- 无法验收时先诊断并继续其他独立工作，记录具体阻塞与恢复条件；未闭环仅能交付阶段结果，不能标为可上线。

## 必需文档与证据

每轮使用 `docs/development/交付验收-YYYY-MM-DD.md`（同日续写）和 `evidence-YYYY-MM-DD/`。已有对应报告可继续使用，不重复创建同义文件。

报告至少包含：目标与范围；代码提交/发布版本/受众；每项用例的环境、期望、实际和证据；失败后的修复与复验；测试数据清理；遗留项与恢复条件。截图只保存必要画面，避免凭证、私人资料和无关用户内容。

PROJECT_MEMORY 仅维护当前可继续工作的状态与报告链接。旧记录标明历史，不把旧测试次数或旧部署状态称为本轮结果。
