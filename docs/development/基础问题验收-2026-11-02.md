# 2026-11-02 基础问题修复与验收

本轮以功能主线为基础，由 QA 逻辑验收、UI 验收和全栈修复三个角色协作，root 负责整合、发布和线上核对。目标是修复已发现的基础问题，形成可部署的 Web 功能版本。以下区分代码验证、生产读取验证和仍未完成的实测。

## 已修问题

| 问题 | 修复结果 | 验证证据 |
| --- | --- | --- |
| 审核员自己的投稿被退回后，修改页面只查审核队列，找不到已退回记录 | 编辑先读取本人的贡献记录，审核员再按需读取审核队列 | 客户端代码复审、类型检查；退回→本人修改→重新提交→审核公开的接口回归通过 |
| 隐藏地点依据过期后无法编辑补充，恢复又要求近期依据，形成死路 | 审核员可补充隐藏地点资料；保存后仍隐藏，核对后再显式恢复 | 普通作者不可修改、审核员可补充、保存后旧链接仍为 404、补齐近期依据后恢复的回归通过 |
| 旧审核页可把已发布或隐藏地点再次退回 | 服务端限制状态转换，过时操作返回冲突 | 已发布和隐藏地点不能再次退回的回归通过 |
| 审核期间地点被更新，旧审核可能覆盖新内容或状态 | 按原状态、内容和更新时间作条件更新；成功后才写审核记录及处理举报 | 模拟并发隐藏、内容变化的回归通过，冲突时不产生通过记录 |
| 修改投稿期间被审核通过或隐藏，旧稿保存可能覆盖新状态 | 投稿修改使用同样的条件更新，冲突时要求重新打开 | 并发通过、隐藏两种情形均返回冲突，不覆盖内容和状态，也不写成功修改记录 |
| 详情社区展示未来时间的空位反馈，与列表规则不一致 | 详情同样排除未来反馈，并保持相同排序规则 | 列表与详情均排除未来反馈的回归通过 |
| 地图代理及停车查询使用 Workers 不支持的 `redirect: 'error'`，生产出现错误 | 改用 `manual`，继续拒绝上游重定向，不跟随到其他地址 | 生产日志定位；地图和停车重定向回归通过 |
| 体验、单项补充、商家确认或到访核对被并发退回后，旧审核仍可能覆盖结果或改动地点 | 审核记录须仍为待审核；涉及地点写入时同时核对原状态、内容和更新时间。同批事务串联地点、审核记录和成功审计，冲突不产生副作用 | 3 项新增回归覆盖体验、补充／商家确认、到访核对；全栈独立复审通过 |
| 密集地图点位互相遮挡 | 已实现屏幕空间聚类、缩放拆分、重合坐标地点选择列表和选中点避让 | 5 项纯逻辑回归及 3 项离线组件生命周期集成测试通过；真实腾讯地图点击、缩放及移动端交互仍待实测 |

UI 角色参与了投稿、审核、隐藏恢复路径的代码审查，并将发现的问题交给全栈修复。代码修改及上述回归已复验；这不等同于桌面和移动端视觉、点击实测全部通过。
