# 数据模型与接口边界

适用范围：早期原生微信小程序准备稿。当前首发改为跨端 Web，请先看 [跨端技术方案](跨端技术方案.md)，此处微信身份与集合不能直接当作 Web 当前实现。

当前实现仅 users、places、review_tasks。其余是后续版本设计，尚无相应提交接口。

| 集合 | 核心字段 | 用途 |
|---|---|---|
| users | _id＝微信OpenID、nickname、createdAt | 私有身份资料；客户端禁止直接访问 |
| places | _id、city、district、name、type、address、latitude、longitude、status | 上海地点底盘；坐标 GCJ-02，后续扩展来源、条件和核验时间 |
| review_tasks | _id、kind、summary、status、createdAt | 审核员队列；来源和证据后续补充 |
| visits，规划 | placeId、userId、visitedAt、conditions、spendFen、attribution | 到访反馈与署名，不公开实时位置 |
| reports，规划 | placeId、userId、reason、observedAt、sourceFingerprint、evidence、status | 用户反馈和独立证据计数 |
| contributions，规划 | userId、objectId、kind、visibility、status | 署名与贡献记录 |
| audit_logs，规划 | actor、action、target、before、after、reason、createdAt | 自动规则和快速审核的可追溯记录 |
| orders，规划 | userId、productId、amountFen、platformOrderId、state | 服务端支付与退款状态 |
| entitlements，规划 | userId、city、sourceOrderId、state | 上海买断访问权限，不依赖客户端 paid 值 |

地点状态：candidate → visited；有失效证据时 suspected_closed → closed；有更新营业证据进入恢复核查。closed 在默认地图与普通详情均隐藏。后续管理员可查看历史；V0.1 没有提供隐藏详情的管理接口。

V0.1 接口：

- `session.login`：创建／读取当前用户，返回其自己的账号标识、昵称、服务端审核权限。
- `places.list`：上海可见地点基础预览，按 _id 分页，每页最多 20 条。
- `places.get`：同样只返回可见基础预览；直接调用隐藏地点返回 NOT_FOUND。
- `review.pending`：仅服务端白名单账号可调用，读取最多 30 条待处理摘要；后续版本增加分页和处理动作。

预览投影不返回完整办公条件、评论正文、其他用户身份、订单或权益。后续付费数据单独做权限校验，不把完整数据先返回再由界面隐藏。

当前没有外部抓取、营业状态同步、同源自动识别或内容检测。规划中的适配器必须能表达 unavailable／unknown，不伪造“交叉核验通过”。
